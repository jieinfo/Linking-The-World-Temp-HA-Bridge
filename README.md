# Linking The World Temp HA

`1.2.3` 是面向 **Linking The World** 小区六恒科技系统的本地 Home
Assistant 原生集成。它通过 MC7021 已启用的本地 `yashcp` TCP/9000 通讯，直接
将六恒总控和房间温控面板接入 Home Assistant；不依赖摩根云、MQTT、Mosquitto 或
MT8157 模拟设备。

本仓库仅发布此 HACS 原生集成。历史 MQTT Bridge 可在 Git 历史中查阅，但不再提供
安装、构建或维护入口。

## 支持范围

- Home Assistant `2026.8.0` 或更高版本；通过 HACS 作为“集成”安装。
- 六恒总开关、制冷/制热/通风/除湿、居家/离家场景、冬季加湿。
- 房间面板自动发现，以及开关、16-28 C 设定温度、温度和湿度实体。
- 科技系统总控的节能状态、温湿度、PM2.5、CO2、系统故障码和滤网故障码只读实体。
- 默认关闭、需在选项中显式启用的实验性节能控制。
- 原生设备、实体、Climate 卡片、HomeKit Bridge 转发、连接状态和运行诊断实体。
- 快速调温只保留最后一个目标值，并等待主机状态确认；不会顺序发送每个中间温度。
- 控制命令优先由主机主动状态上报确认，未及时上报时再合并查询状态，减少与官方客户端并发时的请求压力。
- 总开关、模式、场景、冬季加湿和实验性节能控制共享串行命令队列；同类连续操作只执行最后意图，不同类型
  操作仍按顺序发送。

房间模式由六恒总控决定：总控处于制冷时，房间卡片显示“制冷/关闭”；开启房间
面板不会改变总控模式。通风、除湿或总控关闭时，面板继续显示测量数据，但不允许
作为制冷/制热面板运行。

总控环境与故障数据来自 MC7021 的严格 14 字节完整状态块。系统故障码和滤网故障码收到
`0` 时显示“无故障”；非零值保留主机上报的原始整数，但不等同于某个已知故障名称；
同时创建一个 `ERROR` 级 Home Assistant Repair。相同原始码不会重复告警，原始码变化会
更新现有 Repair，恢复为 `0` 时自动清除。在取得可靠厂商映射前，本集成不会猜测其含义，
故障提醒也不会阻断控制。长度不符合已验证布局的状态块会被拒绝，对应实体保持未知或
不可用，以免把错位字节显示成温湿度或空气质量。

“温度”和“湿度”表示安装在科技系统新风管道、回风口或同类位置的独立传感器经 Mo-Bus
上报并由主机汇总的数据，不表示 MC7021 机身温湿度。`1.2.0` 只修正显示名称，实体 unique
ID 不变，现有仪表盘、历史和自动化引用不会因此复制或失效。

这是社区本地集成，不是厂商支持工具。已知协议证据来自 MC7021 和已交付的六恒总控
虚拟设备、房间面板；不同主机型号、未知固件、未记录的登录响应或不同状态包结构
可能不兼容。首次接入未知固件时请先关闭“允许从 HA 控制设备”，观察有效状态上报后
再逐项启用控制。

## HACS 安装

1. 确认 Home Assistant 为 `2026.8.0` 或更高版本。
2. 在 HACS 的“自定义存储库”中添加：

   ```text
   https://github.com/jieinfo/Linking-The-World-Temp-HA-Bridge
   ```

   类别选择“集成”。
3. 安装 **Linking The World Temp HA**，然后重启 Home Assistant。
4. 在“设置 -> 设备与服务 -> 添加集成”中搜索 **Linking The World Temp HA**。
5. 填写 MC7021 局域网地址、本地主机账号和密码。默认端口为 `9000`；没有确切协议
   依据时，不要改动客户端 ID 和科技系统总控 MAC。
6. 初次登录后会建立总控实体；房间面板会在有效状态上报中被发现。保存过的面板在
   HA 重启后会先显示为不可用，收到新的有效面板上报后恢复。

实验性节能控制默认不注册写入实体。需要测试时，在该集成的“配置 -> 选项”中保持
“允许从 HA 控制设备”开启，并显式开启“启用实验性节能控制”；保存后配置项会自动重载，
总控设备中出现“节能控制”。关闭实验选项后实体会随重载移除，“节能状态”只读实体不受影响。

该写入路径已有协议和自动化组合测试，但尚未替代不同家庭、固件与季节工况的现场验证。
首次使用应在可观察、可恢复的环境中逐一验证，并以主机/App 同步到相同节能状态为成功标准；
不要把按钮点击成功或 TCP 写入成功当作主机已执行。

建议手机 App 使用 `Test` 账号，HA 原生集成使用 `admin` 账号。不要让 App 和原生集成
复用同一个账号；这能减少 MC7021 会话竞争，也便于分辨哪一端正在控制。

## 连接、认证与 Repairs

“主机连接阶段”按顺序表示 `未连接`、`正在连接`、`正在握手`、`正在登录` 和
`已就绪`。只有 `已就绪` 表示已经通过认证且收到了可验证的状态流；TCP 连接成功
本身不是在线。

初次添加集成时，只有捕获到明确的主机拒绝登录响应才会立即显示精确 UI 文案：

> 主机拒绝登录，请检查本地主机账号和密码

这是 `invalid_auth`。运行中的已加载配置项遇到同一种明确拒绝时，会启动现有条目的
重新认证流程，并暂停自动登录重试，直到保存新凭据并重新加载。登录超时、EOF/套接字
关闭、未知响应和网络超时均**不是**坏密码的证据；它们不会显示为 `invalid_auth`。

Home Assistant Repairs 处理可操作的问题：连续三次登录超时会生成一个凭据/主机可达性
Repair；协议不兼容会生成单独的固件/协议 Repair；面板达到长期未上报阈值时生成一个
可确认删除的 Repair；连续三条最终控制命令未获确认时会生成命令链路 Repair，下一条命令
确认后自动清除；主机上报非零系统或滤网故障原始码时会生成对应的严重 Repair，恢复为
`0` 后自动清除。详见 [故障排查](docs/TROUBLESHOOTING.md)。

## 面板持久化与长期未上报

面板记录会跨重启保留。面板平时的“不可用”超时由选项
`thermostat_offline_after` 控制，和长期删除资格没有关系。

长期 Repair 的阈值是 **30 天的已观察缺席时间**，不是最后一次上报距今 30 个日历日。
只有在控制器处于 `已就绪`、有效控制器状态流持续到达、且该面板没有新的有效报告时，
才累积这段时间。HA 停机、主机掉线、认证失败、握手失败、状态流停滞或无效时都会暂停
计时；重连不会清除已经累积的时间。新有效面板报告会清零计时并清除 Repair。

集成绝不自动删除面板。用户必须在 Repair 中确认，才会删除本集成拥有的实体、在安全
时删除设备记录，并最终删除保存的面板记录；取消没有任何数据变化。删除后同一面板
再次上报会被重新发现。

## 隐私与诊断

诊断下载包含连接阶段、失败类别、有限的运行计数、命令确认延迟、总控只读状态、匿名化的
面板/房间标签和非机密选项。它不会包含主机地址、用户名、密码、客户端 ID、任何真实 MAC、
房间名、密钥、令牌或原始协议帧。包括 debug 模式在内，生产日志也不记录原始 TCP 帧；
协议记录仅保留类型、操作码、序列号和帧体长度等安全元数据。

收集给维护者的材料前，请从 Home Assistant 下载集成诊断并只附上该文件和时间范围内的
相关日志；不要手工复制原始协议报文或配置条目。完整边界和安全收集步骤见
[隐私说明](docs/PRIVACY.md)。

## 发布与现场验证

自动化测试使用真实 Home Assistant 测试运行时和可编程 MC7021 假服务器，覆盖协议、
认证、重连、Repair、持久化、动态实体和诊断。它不能替代真实控制器现场验证。

`1.0.1` 已于 Home Assistant `2026.8.2` 与一台真实 MC7021 上验证总控模式链路。在科技
系统关闭时连续执行 20 次制冷、制热、通风和除湿切换，20 次均由主机主动状态上报确认；
确认耗时约 1.06-2.15 秒，兜底查询、重试、最终超时及相关错误日志均为 0。该结果只证明
本次环境中的模式控制路径，不代表所有固件、户型和功能均已现场覆盖；其他环境仍应执行
[发布与现场核对表](docs/TROUBLESHOOTING.md#发布与现场核对表)。

## 发布治理

每个发布在干净的 CI 运行器中执行 HACS 校验、全新 Home Assistant 配置条目加载与重载
烟测。CI 会验证 `manifest.json`、CHANGELOG 首节和 README 标注的版本完全一致；当由
`vX.Y.Z` 标签触发时，还会验证标签与这三个发布事实一致。只有这些检查通过，才创建正式
GitHub Release。
