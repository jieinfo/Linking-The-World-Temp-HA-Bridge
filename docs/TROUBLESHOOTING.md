# Linking The World Temp HA 故障排查

本文适用于原生 HACS 集成 **Linking The World Temp HA 1.0.0**，最低支持
Home Assistant `2026.8.0`。旧 **Linking The World Temp Bridge** 是独立附加组件；
不要让它与原生集成同时连接同一台 MC7021。

## 开始前

- 确认 MC7021 与 Home Assistant 在同一可信局域网，TCP 端口为 `9000`。
- App 建议使用 `Test` 账号，HA 集成使用 `admin` 账号。不要让 App、Bridge 和 HA
  使用同一账号，避免会话竞争和相互掉线。
- 未知主机型号或固件先关闭“允许从 HA 控制设备”，确认总控与房间面板的状态稳定上报后
  再开启控制。该集成不保证兼容未记录的协议回复或状态包结构。

## 连接状态

“主机连接阶段”是运行诊断，不是单纯的套接字状态：

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 未连接 | 没有活动会话，或会话已中断。 | 检查局域网、主机供电和端口；等待受限退避重连。 |
| 正在连接 | 正在建立 TCP 连接。 | 短暂出现是正常的。长期停留时检查地址、路由和防火墙。 |
| 正在握手 | TCP 已建立，正在等待协议握手。 | 确认是 MC7021、端口是 9000，并检查固件兼容性。 |
| 正在登录 | 握手已完成，正在进行本地主机认证。 | 等待结果；不要把此状态单独判断为密码错误。 |
| 已就绪 | 已完成认证，并收到可验证的控制器状态流。 | 这是“主机连接”在线的唯一状态。 |

“连接失败类别”会进一步区分 TCP 被拒绝、TCP 超时、握手失败、登录超时、认证被拒绝、
协议不兼容和状态上报中断。它不含主机地址、密码或原始报文。

## 账号、错误密码与重新认证

初次添加集成时，只有主机发送了已捕获的、明确的登录拒绝响应，才会立即显示这条精确
UI 信息：

> 主机拒绝登录，请检查本地主机账号和密码

这是 `invalid_auth`。请检查 MC7021 的本地主机账号和密码，并确认 HA 使用的账号没有被
App 或旧 Bridge 复用。

已加载的集成在运行期间收到同一种明确拒绝时，不会创建第二个配置项；它会为原配置项
启动“重新验证”流程，只要求输入用户名和密码。提交且验证成功后，Home Assistant 更新
原条目并重新加载；在此之前集成暂停自动登录重试。

**不要把登录超时当作密码错误。** 登录超时、EOF、TCP 关闭、未知登录回复、网络超时或
握手失败都没有足够证据说明密码错误。它们会保留各自的失败类别和重连行为，而不是显示
`invalid_auth`。

## Repairs

在“设置 -> 系统 -> Repairs”中处理以下问题：

- **主机登录连续超时**：只有连续三次登录阶段超时才创建。先检查主机在线状态、端口
  `9000`、账号和密码；Repair 会引导到重新认证。一次成功认证会清除计数和 Repair。
- **主机协议不兼容**：主机返回了当前集成不支持的握手或登录/协议回复。确认 MC7021
  型号、固件和端口；不要为了绕过此问题盲目修改客户端 ID 或 MAC。兼容的成功会话才会
  清除这个 Repair。
- **房间温控面板已 30 天未上报**：这是一个手动清理建议，不会自动删除任何设备。Repair
  仅显示最新房间名、缩短 MAC 和最后有效报告时间；确认后才删除本集成拥有的实体、可安全
  删除的设备记录和保存的面板记录。取消或忽略不会改变数据。以后收到同一面板的有效报告
  时，它会被重新发现并清除 Repair。

### 30 天的准确含义

阈值是 `30 * 24 * 60 * 60` 秒的**已观察缺席**，并非“最后报告日期距今 30 天”。只有
控制器为 `已就绪`、有效控制器状态流持续到达、且该面板未报告时才累积。HA 停机、控制器
断开、登录或握手失败、状态流停滞、无效状态数据都会暂停；重新连接不会抹去之前已累积
的时间。新的有效面板报告会立即恢复可用、将计数归零并移除过期 Repair。

面板短期可用性仍由 `thermostat_offline_after` 控制（`0` 关闭短期检测）；它独立于上面的
30 天清理资格。

## 旧 Bridge 迁移

1. 停止 **Linking The World Temp Bridge**。
2. 安装并配置原生集成，确认总控和每一个房间面板都在“已就绪”状态下正常刷新。
3. 更新仪表盘、自动化和 HomeKit Bridge 以引用原生实体。
4. 确认稳定后，删除旧 MQTT 设备或禁用旧实体。

原生 `entity_id` 在首次添加时由 Home Assistant 创建，迁移不会自动改写旧 MQTT 自动化。
旧 Bridge 的版本、配置和 changelog 与原生 `1.0.0` 无关，仍按附加组件自身发布周期维护。

## 隐私安全地收集诊断和日志

1. 在“设置 -> 设备与服务 -> Linking The World Temp HA”下载诊断。
2. 只收集复现问题前后的一小段 Home Assistant 日志，并同时提供连接阶段、失败类别和
   是否出现 Repair。
3. 不要发送配置条目导出、截图中的账号/地址、主机密码、客户端 ID、MAC、房间名、密钥、
   令牌或任何原始 TCP/YASHCP 十六进制报文。
4. 不要为了排障打开或复制原始协议转储。生产日志不需要原始帧即可关联连接阶段、计数、
   重试和命令确认状态。

诊断会匿名化面板和房间为 `panel_01`、`room_01` 等本次导出内标签，并移除家庭标识。
详见 [PRIVACY.md](PRIVACY.md)。

## 发布与现场核对表

下面是发布前必须在真实 Home Assistant `2026.8` 环境逐项记录的核对表。本文档不声明
任何项目已完成这些现场步骤；不要因为自动化测试通过而跳过它们。

- [ ] HACS 全新安装，配置、首次认证和重启。
- [ ] 重载配置条目，确认设备/实体稳定且没有重复项。
- [ ] 高频房间调温，确认只执行最终目标并得到主机状态确认。
- [ ] 使用手机 App 改变总控和房间状态，确认 HA 被动同步且没有反向误控。
- [ ] 断开并恢复控制器/网络，确认状态变为未连接并自动回到已就绪。
- [ ] 使用明确认证拒绝的测试钩子或受控的模拟配置认证，确认初次 `invalid_auth` 与运行期
  重新认证分别符合预期。
- [ ] 验证登录超时、协议不兼容和长期未上报面板的 Repair 显示、恢复和手动确认删除。
- [ ] 下载诊断，检查不含地址、凭据、真实 MAC、房间名、密钥、令牌或原始帧。
- [ ] 卸载集成，确认集成拥有的后台任务、Repair 和实体按预期清理。
- [ ] 记录已测试的 MC7021 型号、固件、日期、环境和已知限制；未知固件不得标记为已验证。
- [ ] 运行本地质量门和远程 CI/HACS/hassfest 检查，然后才合并和从 `main` 创建 `v1.0.0`。
